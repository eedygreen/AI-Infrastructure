## Rules
1. Only change what the task requires. Do not change unrelated code or files.
2. After every edit, list which blocks of code were changed and why. If you are unsure, ask for clarification before making changes.
3. Run tests after every edit to ensure that the code is still working as expected.
4. Ask me if the task is unclear or if you need more information before proceeding. Do not guess.
5. Read the files in `src` before engaging the tasks. The commit before starting any task should reflect the initial state of the source code.
6. Commit every change with a clear and concise commit message that describes what was changed and why.

## Structure
- `docs/mission.md`: contains the project mission and success criteria.
- `docs/roadmap.md`: contains the project roadmap and implementation phases.
- `src/`: contains the source code for the project.
- `notebooks/unified_retrieval_comparison.ipynb`: unified retrieval comparison notebook.
- `tasks/`: contains the implementation tasks for the project.
- `utils/`: logging utilities.
